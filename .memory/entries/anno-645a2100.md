Hit while building scripts/run_quartr_sweep.ps1 for Task Scheduler.

With $ErrorActionPreference = 'Stop', PowerShell promotes a NATIVE command's stderr output to a TERMINATING error. Python's logging writes INFO to stderr, so a completely healthy sweep ('INFO Using Quartr events tool: list_events') was caught by the try/catch and the wrapper exited 1.

This is a nasty failure mode for a scheduled job specifically: Task Scheduler's 'Last Run Result' would have shown failure on EVERY run while the sweep actually succeeded, so the alerting would have been pure noise and a real failure would have been indistinguishable from the background.

Rule for any PowerShell wrapper around a Python CLI: keep $ErrorActionPreference at 'Continue' around the native invocation and judge success from $LASTEXITCODE. Apply -ErrorAction Stop selectively to the real PowerShell cmdlets (e.g. New-Item for the log dir) instead of globally.

Separately: Register-ScheduledTask with -LogonType S4U ('run whether user is logged on or not') requires ELEVATION and fails with 'Access is denied' from a normal shell. -LogonType Interactive registers fine unelevated; the task then runs only while logged on, but -StartWhenAvailable still reruns a window missed while the machine was off.
