Phase 2 needs something to publish earnings-event manifests into inbox/events. Three routes; two are dead ends.

Quartr REST (QuartrApiClient in Structured Narrative/quartr_history_import.py) is fully implemented and already used by onboard.py, but needs QUARTR_API_KEY, which we do not have and are not getting. Ruled out.

A Cursor Automation calling the Quartr MCP is blocked structurally: Automations can only bind MCP servers registered through the cursor.com dashboard (serverIdentifier prefixed dashboard-, dashboard-team-, or plugin-). Quartr is a project-level .cursor/mcp.json entry and this machine has no ~/.cursor/mcps catalog at all. Prefilling an ineligible server lands in a blocked 'Set up MCP' state that cannot be saved -- and it would only run while Cursor is open, defeating the goal.

Chosen: speak JSON-RPC to https://mcp.quartr.com/mcp directly. Its RFC 8414 metadata reports grant_types_supported = [authorization_code, refresh_token], token_endpoint_auth_methods_supported = [none], plus a dynamic registration endpoint. There is NO client_credentials grant, so a token cannot be minted from a secret alone -- but refresh_token means a human signs in through the browser exactly once and every run afterwards mints its own access token. Genuinely headless, no API key, no editor session.

Shape: quartr_oauth.py does RFC 7591 registration + PKCE authorization_code over a loopback redirect, persists to host_quartr/.quartr_oauth.json (gitignored; the refresh token is a live credential with no other copy) and refreshes with a 120s skew so a token cannot die mid-sweep. quartr_mcp.py is a streamable-HTTP JSON-RPC client whose QuartrMcpGateway satisfies the same list_events(*, ticker) contract as the existing JSON-dump gateways, so publish_calendar cannot tell the difference and stays covered by its tests.

The events tool is discovered from a live tools/list rather than hardcoded, scored to avoid Quartr's event-detail and transcript tools (which take an event id, not a ticker), overridable via QUARTR_MCP_EVENTS_TOOL. 'calendar --source mcp' writes dumps to disk and then publishes from disk, so the audited file path stays the only publish path and there is a record of what Quartr said the day an event was armed.

Outstanding: the one-time browser sign-in has not happened, so the resolved tool name is unverified against the live server.
