Cursor writes MCP results above roughly 20 KB to agent-tools/<uuid>.txt and returns only a one-line pointer (~50 tokens); smaller results are inlined and NOT written to disk.

Consequences for bulk transcript pulls:
- read_transcript first window (~60-100 KB) → file. Cheap in context.
- fromTimestamp continuation tails (~10-20 KB) → inline, ~4k tokens each and not on disk. Workaround: pull `section: "qna"` instead (large enough to hit the file path; overlaps the first window) and de-duplicate by paragraphId — merge_windows() in _desk_transcript_backfill.py does this.
- list_events with a wide range (~45 events) → ~5k tokens inline. Use narrow startDate/endDate per ticker, or accept the cost once and register ids with `events --add`.
- Old agent-tools dumps persist across sessions: registering event ids can surface transcripts pulled in earlier sessions for free (AMD FY2016 did).
