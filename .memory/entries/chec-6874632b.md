State: 'host_automation calendar --source mcp --horizon-days 100' publishes 47 manifests covering all 45 onboarded companies, zero skips, zero rate-limit failures. Suite 849 passed. Nothing committed.

Four bugs surfaced, all invisible in unit tests and all found by calling the live API:

1. list_events takes companyId, not ticker, and 'expand' is a REQUIRED array. My gateway passed {ticker}. Every sweep would have failed input validation and read as 'no upcoming calls'. Fixed with a cached search_companies lookup that demands an EXACT ticker match (Quartr search is fuzzy; arming the wrong company is worse than skipping one) and expand=[contentDates].

2. _fiscal_period took the quarter from the title but the year only from row['fiscalYear']. Quartr returns fiscalYear=None on many live rows while still titling them 'Q3 2026'. BMY, IBM, LLY and MRK produced no period and were dropped in silence -- four major names that would never have been armed. Fixed with a title-year fallback; an explicit fiscalYear still wins.

3. Quartr returns multiple events per quarter. MU FY2026-Q4 came back as the call at 20:30Z AND a 'Q4 2026 Post' session at 22:00Z. Both map to one manifest filename and one unique (ticker, fiscal_period) row, so the winner was whichever was written last -- Roz could have been armed against the post-earnings session. dedupe_by_period now keeps the earliest call time, which is a property of the schedule rather than of Quartr's title wording.

4. Quartr estimates report and call timestamps INDEPENDENTLY, so for a quarter months out they drift apart: GILD call Oct 29 / report Nov 6, NVDA call Nov 18 / report Nov 25. 32 of 47 rows were inverted. This violates Roz's call_at >= report_at invariant, and the raised ValueError ABORTED the entire sweep, leaving 6 of 47 manifests written with no obvious failure. Two fixes: report_at is clamped to call_at (results are necessarily public by the time the call starts) and the per-manifest write is now guarded so one bad row is recorded as a skip instead of ending the run.

Also: Quartr rate-limits a full-book sweep partway through (HTTP 429 with retryAfter). _send now honours Retry-After from header or body with capped backoff. The 'keep the previous dump when a fetch returns nothing' rule saved the first sweep -- worth keeping.

Open: the 32 clamped report times are Quartr ESTIMATES and will be corrected as dates firm up; T-7 re-verification (Phase 3b) is what fixes them. The sweep is not yet on a timer, so the cycle still needs a manual invocation.
